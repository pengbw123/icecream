## 建议实施顺序

1. **先完成正式音频闭环和PCM对照**：确认PC UART和25K中转能独立演奏；继续Dexed板端PCM采集/比较。运行时编辑参数不保存是当前已知限制，不算串口失效。
2. **初始化路径分拍**：把算子索引选参、键位缩放和对数电平合成拆成明确寄存器阶段，维持现有整数舍入/饱和顺序。增加少量FF和状态拍，换取可复用的时序余量。用参数级差分确保不改变音色数学结果。
3. **先32复音**：继续单通道流水线，不以增加DSP为目标。修正所有地址、计数、显示和分配逻辑，验证密集Note On及延音尾音占用。
   - 当前VOICE_BITS只分4/5位，超过32需改为clog2。
   - 算子状态读写地址固定7位，32×6=192槽需要8位，64×6=384槽需要9位。
   - 活动声部计数及top/显示接口为5位，不能表示32，需扩到clog2(VOICE_COUNT+1)。
4. **再评估64复音**：状态存储随声部数增加，DSP不一定线性增加；当前扫描骨架约12V拍/音频帧，另加流水线排空、输出和事件处理。32声部骨架约384拍，64约768拍，仅作代码结构估算，不能当最坏情况实测。需加入帧周期/超时计数并仿真高事件压力。
5. **需要更高吞吐时加2～4路计算通道**：按声部分组，各通道维护自己的反馈/总线/状态RAM，参数同步广播，最后宽位混音。能真正利用更多DSP、BSRAM并降低每路排程压力，但也增加路由和事件分配工作；不能直接复制顶层、同时接收同一Note On，否则只是同音叠加。
6. **音色精度优先于单纯堆声部**：继续核对指数增益、乘法中间位宽、AMS连续深度、反馈总线截断/溢出，必要时增加表精度和共享乘法级。位宽增加须对照Dexed明确目标量化规则，不是无限加位就会更接近。
7. **可旁路立体声效果器**：恢复并改良混响/合唱，加入立体声处理与音量余量策略；效果器会用更多延迟存储和DSP。保持原声旁路用于音色对照。现有单MAX输出不能完整展示立体声，最终输出硬件需配套。
8. **显示与控制扩展**：实际PCM FFT频谱、算法连线/EG编辑页、CH376S输入、板载Codec与音色持久化按优先级加入。FFT应分析真实PCM，不用参数柱状图替代。

## 推荐目标

先争取“32复音 + 更高音色一致性 + 可靠输入/PCM采集”，再推进“64复音 + 可旁路效果器 + 完整屏幕编辑”。若还需更高声部数，再以2路/4路音源流水线扩展，而不是为了让资源百分比好看而增加无用电路。
资源数字与Fmax必须每阶段重新综合/PnR更新。当前并未实现32/64复音或提高主频，也没有在本轮修改FM内核。
