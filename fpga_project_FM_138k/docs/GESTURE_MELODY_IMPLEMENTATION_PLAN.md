# 手势旋律演奏：实现检查

本文件保留早期实现检查。当前实现与验证入口已完成，功能说明见GESTURE_PERFORM.md；最终下载发布状态以release记录为准。

- 现有手势接口 `gesture_config` 仅有识别和控制两位，手势动作当前映射为握拳停止、张掌开始、V变奏。增加演奏模式需要明确独立的模式配置与界面，保留原有映射。
- 现有 `phrase` 是两个64步的乐句缓冲；`lock_pending` 到第63步完成后切换整段回放。它不是上一小节循环，不能直接把握拳映射到现有LOCK就声称实现16步小节锁定。需要跟随当前四分音符节拍定义、缓存完整上一小节，处理首次不足一小节、延音、NoteOff、切换与退出。
- 当前 V 动作4立即改变随机状态和变奏步数，若要在下一小节生效需要增加待执行状态，并约定停止、手动操作、锁定循环和新变奏的优先级。
- 手位置尚未输出到旋律引擎。当前已输出256位二值轮廓；应该只在新鲜、识别通过、稳定张掌时提取位置，并保持最近有效位置，拒识/断流不产生跳变。以三档加迟滞抑制抖动，在拍点提交密度/方向，避免与触屏配置互相覆盖。
- 验证应覆盖两种模式、手动优先、识别丢失、手势去重、初始无完整小节、跨小节锁定/恢复/变奏及音符关闭，并重新检查完整工程时序和BSRAM使用；当前50 MHz时序余量较小，保持既有约束。
