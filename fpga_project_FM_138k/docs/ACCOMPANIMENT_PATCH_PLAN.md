# 伴奏固定音色原始方案

> 当前已实现 LIVE/BACKING 两 Part，使用方式、实际边界和协议以 TWO_PARTS.md 为准。以下保留作为此前方案记录。

用户允许不容易实现时本轮先给方案。当前32复音仍是单音色音源：算子音量/包络、算法与反馈、LFO、Pitch EG都引用全局参数。保存预设编号不能让伴奏在换音色后保持原声，用户自编音色也不能只用ROM编号表示。

建议两声部：LIVE（即兴）和 BACKING（ARP或SEQ，现有两者互斥关系保留），共用现有32个物理声部和渲染流水线。

1. 为完整音色参数增加双银行；每个物理声部保存所属 part。音源运算按 part 读取对应算法、算子和包络参数。
2. LFO相位/延迟/同步、Pitch EG、踏板及音符所有权也按 part 分开；不能只复制算子频率和音量。相同音高的两 part 必须能各自发声和松键。
3. ARP 在首次建立背景和弦时抓取当前完整音色；可提供显式 `CAPTURE PATCH`。HOLD后 LIVE 换音色只修改 LIVE 银行。
4. SEQ 每个 Pattern 保存一份完整音色，在首次录制/明确捕获时更新。播放开始将其装入 BACKING 银行；改变 LIVE 音色不改 Pattern 快照。SD Pattern 保存另立格式，当前SD音色库只存用户音色。
5. 用户换音色不清除 BACKING 声部；伴奏 STOP 不清 LIVE。32声部统一分配，但抢音优先级需明确，避免背景占满后即兴按键无声。
6. 首版 FX 仍共享主输出，单独效果链将进一步增加 RAM；需在UI说明共享效果的行为。

这会触及分配器、实时算子取参、LFO/Pitch EG和命令提交逻辑。现主时钟时序余量小，必须补充跨part同音/独立包络/换音色不中断/满载deadline和逐样本回归，再进行完整布局布线。本轮未用临时音色切换来冒充独立声部。

## 本轮已经实现的 HOLD

- HOLD + ARP页：继续编辑背景和弦，松开后再按新和弦可以替换。
- HOLD + 其他页：背景和弦锁定，所有新键直接演奏；切页不停止节拍或重置序列。
- 即兴音符在返回ARP页后松键仍能正确结束；离页后才松开的原和弦键不被误当成即兴松键。
- bit30的ARP音符加入与人手演奏的所有权保护，避免同音时互相提前关音。当前同音仍共享一个音源声部，并非双音色。
- 当前踏板状态全局共享，HOLD即兴模式不把踏板按下传给音源，防止ARP的门限失效、所有背景音持续叠加。独立踏板行为留给上述part改造。
- ARP/SEQ互斥、练习模式暂停ARP、STOP/USB断开清音等既有规则保留。
