## 菜单与操作

入口：**SETUP → AI BASS → COMPOSE > → SETTINGS → GESTURES >**。保留原来的SETTINGS/SURFACE切换和底部全宽琴键。

- `RECOGNITION`与`CONTROL`上电都OFF。先只开RECOGNITION，检查HDMI方框、RAW/STABLE、FRAMES和状态。RGB-only构建会显示UNAVAILABLE，不会误置开关。
- 识别开启后，HDMI显示中央96×96源像素对应的方框，底部只留一行NN状态，原四行摄像头诊断收起以免遮住手。关闭识别后恢复原四行诊断；复用同一份字体ROM。
- `CONTROL`需单独开启。CONTROL ARMED表示开关已开；CONTROL ACTIVE还要求COMPOSER持有BACKING、没有录入/学习/紧急停止，且有新鲜识别帧。无摄像头时不会因开关开启而产生音符。
- 开启控制时已持续保持的手势不会重放旧命令。先移开手或换手势，再进行控制：握拳STOP、张掌START、V变奏。已播放时再次张掌不重置乐句。
- 手动触屏/打击垫命令优先，并撤销旧手势命令；保持同一手势不能立刻撤销手动STOP。录主题、录节奏、学习打击垫期间禁止手势控制。紧急停止后须手动START恢复。
- 切到其他页面时可保留COMPOSER和手势开关；退出COMPOSER模式/切换自动演奏模式时自动关闭CONTROL，保留仅识别显示。未进入COMPOSER时不能通过手势抢占其他模式。
- RAW是最近一次网络分类，STABLE是连续三帧确认的分类。UNKNOWN不等于已证明“没有手”。GAP/256是原始分数间距除256并饱和到255，**不是百分比概率**；FRAMES超过999显示999+。

UI固件仍为80KiB指令ROM、96KiB数据RAM。本轮使用LTO，并让常用绘制函数保留独立调用，避免复制多份绘制代码；最终镜像80404字节、BSS10804字节、栈余17900字节，没有扩大存储。

具体交互：手掌进入中央方框并保持三个有效识别帧，张掌请求START，握拳请求STOP，V手势请求变奏。保持同一手势只发一次；换手势，或连续三帧未通过识别后，才能再次触发。START沿用COMPOSER原有的开始乐句语义；停止时不会改变LIVE手动音符。**由于摄像头尚无实机图像，当前仍没有实际手势控制成功的证据。**

暂不做任意背景中的手掌定位、多人、多手或连续手部关键点。今后若要在复杂背景中工作，应加入手部检测/裁剪及真实背景的无手负样本，必要时升级小型CNN，而不是不断放宽阈值。

## 我在哪里、怎样训练的

训练在这台电脑的CPU上进行，使用Python、NumPy和Pillow；FPGA只负责推理，不训练。
数据是 Laurence Moroney 的 Rock Paper Scissors：握拳、张掌、V手势，CGI生成、白背景。
来源和下载链接按 [TensorFlow官方数据集构建器](https://github.com/tensorflow/datasets/blob/master/tensorflow_datasets/datasets/rock_paper_scissors/rock_paper_scissors_dataset_builder.py)；作者的[数据说明与许可](https://laurencemoroney.com/datasets.html)明确其CGI来源、白背景和CC BY 2.0许可。

- 原始2520张训练图片：2160张训练、360张验证。验证集按整个文件名序列隔离，不把同一序列的相邻帧随机拆到训练与验证。
- 官方测试集372张，未用于梯度训练或选择训练轮次。验证集选取最佳INT8模型。CGI身份是否跨序列重合未知，不能当作真人跨身份评估。
- 固定随机种子720138，180轮；选中第144轮。验证准确率97.22%，官方测试集 **304/372，即81.72%**。
- 曾比较灰度输入与轮廓输入。灰度版验证92.78%、测试75.81%；轮廓版按更高的验证准确率选用。测试集已经在本次开发中查看过，后续继续优化应另留新的实拍验收集，不把它当作从未接触的盲测集。
- 轮廓来自简单的亮度阈值，**这部分是固定逻辑预处理，三类手形判断才是训练得到的神经网络**。这不是肤色检测，也不适合任意深色背景。
- 没有训练“无手/其他”第四类。分差、像素面积和连续帧过滤能减少一部分误触发，不能保证陌生物体或背景一定拒绝。

训练源码在 `tools/gesture/train.py`，预处理与整数参考在 `model.py`；训练日志 `assets/ai/gesture/training.log`。
权重、偏置、372组测试图像的取样特征、预期分数和数据SHA256在 `src/generated/gesture/`。
原始ZIP和下载分块仅存在忽略的 `tmp/gesture_data/`，不提交整个数据集。

```powershell

python tools/gesture/train.py --features silhouette --epochs 180
python tools/gesture/check_export.py
```

## 硬件实现与接口

`gesture_pipeline.v`是独立识别核心，外层`gesture_controller.v`已在`camera_hdmi_tx.g_gesture`实例化。相机捕获器的`pixel_write/address/data`及`frame_start/good/bad`作为输入，尺寸固定160×120、RGB332。RGB屏和HDMI不参与神经网络计算。

1. `gesture_roi.v`：中央96×96区域（x32..127、y12..107），每6像素取一个单元中心，得到16×16输入。RGB332按R/G/B=1:2:1计算亮度，暗度≥12标记前景127，否则0。训练也先做同样的RGB332量化与点采样，不使用不同的双线性缩放。
2. `gesture_mailbox.v`：256×7位特征小缓存，单银行、请求/确认toggle跨域；特征和面积保持到推理完成。没有空银行时丢整帧，不覆盖正在使用的数据。共同复位，各域同步释放。PCLK停止不妨碍系统50MHz域运行。
3. `gesture_mlp.v`：6216个INT8权重、27个INT32偏置，单MAC时分复用。隐藏层算术右移6位、限幅0..127，输出三项有符号分数。单次推理12486周期，在50MHz下249.72微秒，另外有约10微秒的特征重放时间；不是从用户动作到最终声音的总延迟。
4. `gesture_events.v`：初始工程门限为第一/第二名分差≥2048、前景总值768..30000；连续三帧确认。同手势去重、三帧拒绝后重新允许相同手势、默认1秒无结果后撤销跟踪。门限不是已校准的可靠性保证。

`recognition_enable`允许取样，识别稳定性与CONTROL开关独立；`control_enable`另外允许生成演奏命令。两个开关默认0，先只显示诊断，再由用户启用控制。动作是COMPOSER的START=2、STOP=3、VARIATION=4，不是MIDI音符。
`action_valid/action_ready`为握手，等待接收时命令保持不变；未接收期间换手势，则等后续识别帧再尝试。丢失画面超时或关闭控制会清除待发命令。

主旋律入口已经增加触屏/打击垫/手势仲裁和模式所有权检查：UI/垫优先，白名单仅允许动作2/3/4。控制器增加一拍弹性命令寄存，避免MIDI判定信号穿过识别控制又返回音乐调度路径。HDMI状态包使用垂直消隐请求、主时钟持有包/应答的跨域握手，不逐位异步拼接多位数值。

寄存器：UI[63]写bit0识别、bit1控制；识别OFF强制控制OFF。读bit2=该构建支持手势、3=摄像头配置ready、4=fault、5=有1秒内新结果、6=稳定跟踪、7=推理busy、[9:8]=RAW类别、[11:10]=STABLE类别、12=待发命令、13=控制实际可用、[15:14]=上次已交付命令（1STOP/2START/3VAR）、[31:16]=饱和结果计数。UI[35]读[14:0]=前景能量、15=本次分差/面积门限通过且新鲜、[31:16]=饱和到65535的原始分差。ready仅说明相机配置完成，不说明有完整图像，必须同时检查fresh/FRAMES。

权重和偏置仅6324字节，另有小型激活与跨域特征缓存，没有增加整帧缓存。相对当前324/340个BSRAM，容量预算有机会容纳；最终映射块数、DSP、布线和50MHz是否满足，需要统一综合与PnR报告，当前不给出实测资源承诺。

## 验证边界

专项包括：372张测试图全部1116项分数逐位比较、推理固定周期、忙时写入/重复启动忽略、中途复位；RGB332亮度与取样坐标/面积；坏帧、缺像素、忙时整帧丢弃；异步时钟邮箱、保持数据、停PCLK和复位；三帧确认、短暂抖动、低分差/空白拒绝、长时间持有、背压、超时和关闭控制；三类公开样本的RGB332帧经取样→跨域→网络的联合仿真。

增加了真实公开样本连续帧→控制器→实际COMPOSER的联合验证：只识别不控制、启用时不重放旧手势、手动STOP优先、换手势重新触发、开始/停止/变奏无挂音，以及停PCLK/重配置后的过期数据处理。菜单使用真实RV32I固件和引脚级Goodix模型验证开关与跨页面状态；既有FM32/I2S与MIDI入口另作回归。

上述都使用文件或仿真像素，**没有真实摄像头采集成功的证据**。连续帧准确率和误触发率未测。下一步优先获取实际图像，在不同手、距离、亮度、无手背景下收集序列；按人或录制场次分训练/验证/验收集，再决定是否升级CNN。本轮统一构建全部识别/菜单/显示/仲裁模块，不为每个小模块单独跑PnR。
