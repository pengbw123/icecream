# 辅助演奏第一版

## 实机入口与使用

- SETUP → 右列最下一行 **PRACTICE**。
- 顶部保留八个菜单页签，点 PLAY 或其他页签退出练习。
- 下方保留 800×128 全宽触屏琴键，范围 MIDI 48..72（本机标记 C3..C5）。
- 默认 **MODE: WAIT**。START 后经过约两秒引导，音符滑条下落到琴键上方判定线；
  时间停在待弹音符处，收到正确音高的**新 Note On** 才继续。提前一直按着不计入，
  重复音要松开再弹；错音正常发声但不推进曲目，Note On 力度零按松键处理。
- **MODE: DEMO** 自动播放；使用当前音色、效果器和统一主音量。
  当前示范力度固定为 96，曲目表不保存原 MIDI 的力度、踏板、弯音和音色切换。
- START / PAUSE、RESTART；SPEED − / + 在 50%、75%、100%、125%、150% 中选择。
  RESTART 回到开头并暂停；结束后 START 可重新播放。切换模式也回到开头并暂停。
- 暂停会发出示范 Note Off；恢复时从当前时间继续，已释放的半截长音不会重新起音。
- 触屏和外部 USB MIDI 键盘均可练习；PC UART 注入的正常 MIDI 同样可被判定。
  进入时固定显示八度为 0，临时关闭单音滑音并释放延音踏板，退出恢复原八度和滑音开关。
  延音踏板状态不自动恢复；请在进入/退出时先松开键与踏板。
  自动演奏功能加入后，练习期间也会屏蔽 CC64 延音，避免全局踏板使示范音累积或退出后挂音。

内置曲目是公版旋律《小星星》（TWINKLE），自行录入 42 个旋律音符，C4..A4。
默认四分音符 512 ms，约 117.19 BPM；引导 2.048 s，全曲含引导 26.624 s。
每个音符预留 64 ms 松键间隙。第一版长条表示时值，不对实际松键时刻、节奏或力度评分。
仅单音旋律，不包含和弦判定、伴奏、五线谱、曲目列表、USB/蓝牙/SD 接收驱动或掉电存储。

## 硬件结构

- `lesson_player.v`：50 MHz 域的独立毫秒时基、16 ms 曲目刻度、变速、等键、示范事件及
  暂停/退出清理。不会等待软核轮询或屏幕刷新；MIDI 输出有 ready/valid 握手。
- `lesson_score_memory.v`：128×32 位工厂 ROM + 128×32 位上传 RAM。播放、RGB、HDMI
  各有独立同步读端口/副本，接收同一份写入，工厂库不被上传覆盖。复位恢复工厂库。
- `lesson_view.v`：两块屏幕复用同一个纯 RTL 模块。每行消隐顺序扫描 128 个事件，
  生成下一行的 25 键音符掩码；HDMI 的 160 个消隐时钟足够容纳 128 次读和流水延迟。
  全宽黑白键与滑条使用相同几何坐标。RGB 为 800×480，HDMI 为 640×480；
  引导区域 y=128..351，琴键 y=352..479，默认提前可见约 3.58 s。
  键位/边界由同步几何 ROM 预取，避免把实时除法和反算边界串在像素时钟的一个周期内。
- 时间、状态、按键掩码通过请求/应答保持的多位快照跨时钟，只在消隐更新。
  每个显示器独立刷新；PLL 丢锁重置快照双方，恢复后重新获取完整状态。
- `midi_note_owners.v`：示范内部事件以 bit31 标记，MIDI channel 不作占用。
  手动和示范同音时共享一次发声，任一方松键不会释放另一方仍持有的音；普通手动重击保持。
  所有权判断后有一拍弹性队列，隔离 128 位掩码选择和 FM 事件解码的组合路径。
  判定器看到音频入口队列接受的原始事件，包含因所有权而未转发的手动事件，且忽略带示范标记的事件。
- 软核只绘制文字、选择模式和写控制寄存器；无逐像素 GUI、帧缓冲、DDR 或新增厂商 IP。

## 后续 USB / 蓝牙 / SD 适配接口

先把 MIDI 文件转换成统一的事件表，再由接收端逐项写入；不要让通信协议参与播放时基。
当前保留 **128 事件、单音旋律** 容量，不等于可直接接收任意完整多轨 MIDI。
后续扩容/和弦可增加格式版本和存储容量，现有显示/时基与通信接收层仍可分开使用。

事件字（32 位）：

| 字段 | 含义 |
| --- | --- |
| [31:16] | 起始时间，单位 16 ms，包含引导 |
| [15:7] | 持续时值，1..511 个刻度（最长 8.176 s） |
| [6:0] | MIDI 音高，48..72 |

起始时间递增，不能与前一音符重叠；起始+时值不能超出 65535。
上传库为 RAM，掉电丢失；工厂 ROM 始终保留。

### 软核寄存器（UI 基址 0x23000000，表内为 32 位字索引）

| 索引 | 写入 / 读取 |
| --- | --- |
| 28 写 | bit0 enable、bit1 run、bit2 demo、bit3 restart 脉冲；[15:8] 速度百分比 50..150 |
| 28 读 | bit0 enable、1 run、2 demo、3 waiting、4 done、5 清理/示范占用；[14:8] 下一音高，[31:24] 已通过/已发出的音符数量 |
| 29 读 | [15:0] 时间；bit16 enable、17 run、18 demo、19 waiting、20 done；[31:24] 索引 |
| 30 读 | [7:0] 曲目音符数，bit8 上传库选择，[31:16] 曲目结束时间 |
| 31 写 | 1=开始/重新开始上传，0=中止上传，2=恢复工厂库；仅 enable=0 且占用位=0 时接受 |
| 31 读 | bit0 uploading、bit1 error、[9:2] 已接收数量 |
| 32 写 | 事件地址 0..127 |
| 33 写 | 事件数据字；只允许地址从 0 连续递增，内部逐项检查音域、时值、顺序、重叠和溢出 |
| 34 写 | 原子提交：[7:0] 数量、[31:16] 曲目结束时间；必须等于已接收数量且结束时间不早于最后一个音符结束 |

建议接收流程：先写 UI[28]=0，轮询 UI[28] bit5=0，再 UI[31]=1；依次写地址/数据；
最后提交。上传期间不允许启动播放；校验出错后拒绝提交，必须重新开始或中止。
接收任务必须先在页面层退出练习，完成后再允许进入，以免页面状态与传输过程相互覆盖。
当前错误上传不改库元数据；若正在重写已经选中的上传 RAM，中止后应恢复工厂库或重新上传，
不能保证旧上传曲目的内容仍然完整。后续需要无损更新旧用户曲目时应再加第二个上传 bank。

`tools/midi_to_lesson.py` 不依赖第三方 MIDI 包：支持 SMF 0/1、PPQN、tempo map、running status、
零力度 Note On 和通道选择；拒绝复音/缺少松键/越界，输出版本化 JSON 与 RAM `.mem`。
去除首音之前的空白，再补 128 刻度引导。当前忽略延音控制器，以显式 Note Off 作为时值。

```powershell
python tools/midi_to_lesson.py docs/lesson_twinkle.mid --output tmp/lesson.json
# 多轨素材可选择单个旋律通道（1..16）
python tools/midi_to_lesson.py song.mid --channel 1 --output tmp/song.json
```

工厂曲目和参考 MIDI 由 `tools/generate_lesson.py` 同时生成，参考文件不是从第三方曲库复制。

## 验证

- `tb_lesson_player`：错音、重复音、零力度、等键停时、变速、暂停、MIDI 反压、重来、完整 42 音、上传库、退出。
- `tb_midi_note_owners`：手动/示范交叠，两种松键顺序、普通重击、All Notes Off、反压。
- `tb_midi_owner_queue`：队列停顿保持、事件顺序、音色亮度随事件锁存、同音所有权。
- `tb_lesson_loader`：总线装载、提交、音域/顺序/复音拒绝、播放期间禁止装载、工厂库不被覆盖。
- `tb_lesson_view`：RGB/HDMI 滑条音高对齐、长条、琴键高亮、消隐快照、PLL 丢锁恢复。
- `tb_touch_ui +lesson`：真实 RV32I + Goodix 引脚模型，入口、完整琴键、模式、速度、播放/暂停、重来、退出。
- `tools/tests/test_lesson_import.py`：工厂 MIDI/ROM 往返一致、tempo/running status、复音/音域/通道选择。

发布构建与实机验证状态见 `AI_HANDOFF.md` 最新章节。软件仿真不能代替触屏手感和实际 MIDI 延迟验证。
