# 后续开发顺序（2026-10-24 与用户确认）

按下面顺序逐项推进；每项应先仿真、检查资源和时序，再由用户实机验证。
本次授权实现第 1 项，后续项目记录为计划，不表示已开始或已交付。

1. **性能监测**：被动 RTL 统计、菜单快照、超时与丢事件诊断；增加可核验的性能证据。
2. **32 复音**：修正地址/计数位宽，测量最坏调度周期，优化时序和 RAM，检查抢音与混音余量。
3. **多分区与八垫鼓组**：通道和音符归属隔离，键盘/鼓组同时演奏；实时 FM/噪声合成，鼓件独立参数。
4. **自研 XY 演奏**：两个独立连续控制维度，对应原题自研多维交互要求。
5. **SD 保存**：音色、Pattern、曲目和 MIDI 演奏事件持久化。
6. **立体声**：声部声像、鼓组分布、立体声效果处理。
7. **64 复音**：根据 32 复音实测结果增加并行运算通道，不能只修改 VOICE_COUNT。

补充候选：8 位数码管显示音色/复音、BPM/步号或测试状态；多轨音序器；独立频率现场测试模式。
蓝牙由用户后续单独安排。

## 设计依据

- 原题《2026（高云半导体）选题指南》印刷页 13–14：≥32 复音是拓展目标；
  核心吞吐量为同时活跃可闻独立振荡器数量 × 实际采样率；FM 按运算器统计。
- 不是靠填充无用逻辑提高占用率；真实可用吞吐量、低延迟和稳定性应能测量验证。
- 性能监测前基线：16×6 FM，Fs=48.828125 kHz；Logic 40,739，FF 20,789，
  BSRAM 314/340，DSP 65/298；50 MHz 主域 Fmax=50.007 MHz。
- 不把配置容量、已分配声部或输出谐波数量直接当作比赛的活跃可闻独立振荡器数量。
