# 2026-10-30 32x32灰度算法基础

## 已完成范围

新增独立RTL前端 `gesture_gray_frontend`，由 `gesture_gray_roi` 和 `gesture_gray_mailbox` 组成；已加入Gowin工程文件列表，尚未实例化到生产顶层。当前下载位流和原三类识别/手势音乐控制不变。没有新增训练好的CNN，也没有声称解决复杂背景识别。

输入为经过几何校验的160x120 RGB565流；中央96x96区域(x32..127,y12..107)每3x3单元取中心，即x33,36,..126/y13,16,..106，输出32x32。RGB565各通道按高位复制扩展到8位，灰度采用 `(R+2G+B+2)>>2`，黑0白255。这是便于RTL的近似亮度，不是标准BT.601转换。不二值化、不反相、不做逐帧自动归一化。未来训练必须沿用同一公式。

每帧1024个8位样本，原始图像容量1024字节；灰度和18位，最大261120。邮箱为单银行1024x8双时钟RAM，发布后保持到消费者done。没有空银行时丢整帧，不覆盖在处理的数据。坏帧、缺少取样点、半帧禁用不发布。

消费者在50MHz域每两拍获得一个feature_write有效点，索引0..1023顺序输出，随后frame_valid单拍表示输入全部送完。feature_sum同时有效。接口没有逐点背压，消费者必须接收全帧；CNN做完再发done，done不得早于frame_valid之后。正常重放约41微秒，不含摄像头采集与CNN推理。关闭enable只停止新采集，在途任务仍需消费者完成，或共同复位。reset_n必须覆盖两个域，不能独立复位邮箱一侧。

## 资源与验证

在同款GW5AT-LV138PG484AC1/I0 B上独立Gowin综合通过：1块BSRAM、167寄存器、172 LUT、78 ALU、0 DSP。LUT/ALU是综合原语分类，不能直接等同整工程PNR报告Logic。综合报告和日志在 `assets/gesture_gray/`；没有对新增模块完成布局布线或STA，84.75MHz仿真不能替代物理时序验收。

当前正式构建BSRAM331/340、逻辑72624/138240、寄存器43094/139095、DSP85/298。仅灰度前端账面增加1块BSRAM约为332/340，仍需集成后验证。它不代表任何CNN都能放下。后续需要限定网络通道数、权重大小和特征缓存复用；双银行、32x32特征预览或额外CNN输入副本都需额外计费。

验证包括：所有65536种RGB565灰度转换逐项比对；异步84.75MHz PCLK/50MHz系统；9216个样本的索引、灰度和帧总和；全黑/全白及18位总和边界；消费者忙时丢帧、坏帧、缺样、半帧禁用、停PCLK、在途共同复位和恢复；Python预裁剪训练适配器与160x120硬件坐标/量化匹配。

## 与当前摄像头的集成边界

生产 `ov5640_capture` 在800x480 RGB565字节拼接后裁剪/降采样为160x120 RGB332。新接口需要在RGB332压缩前，给相同选中像素增加RGB565抽头，并严格复用同一帧有效/坏帧判定。当前还没有接入这个抽头，不能把32x32灰度直接送给旧256输入二值模型，也不能把RGB332还原成RGB565当成恢复了原精度。

## 复现和下一阶段

```
./sim/run_gray_checks.ps1 -IverilogDirectory <iverilog-bin> -Python <python.exe>
```

`tools/gesture/gray_reference.py` 提供RGB888→RGB565、RGB565→灰度、160x120→32x32精确参考。`roi_image_features`只接收已经裁好的正方形手部ROI；将素材转成96x96是数据适配步骤，不代表已实现手部检测，不能直接喂任意全景图片训练。

下一阶段先离线训练小通道INT8 CNN（包含无手/其他负样本），保存独立验证集和背景/曝光压力测试；确认相对现有方案有效，再做卷积MAC/缓存RTL、抽头与预览集成及整工程时序验证。真实复杂背景准确率仍未知。
