# 138K 等键练习与MIDI自动演奏（2026-10-23）

App提速候选0.4.6-r1沿用本页同一份FPGA文件，无需因本次App升级重新烧录。上传设置默认“自动提速”：读取有效板端能力，115200且支持窗口时每组最多8事件；FFE1支持时仅批量事件采用无响应写，仍等待整组FPGA回复和最终CRC封存。未知能力保守逐帧，旧手动模式保留；可选“115200逐帧确认（兼容）”回退。传输错误会中止，不能在上传中途切模式续传。实际速度待手机复测。

此版本增加《晴天》“弹对再走”和独立MIDI播放器，配套App为0.4.5-r3。RTL仿真、综合和时序检查已通过；手机、键盘、灯带和声音仍待用户实板验收。下载/烧录由用户操作。

## 弹对再走

选择“弹对再走 · 先学指法”，再点开始。App先停止旧指引，设置方式、速度、移调和灯位，逐帧得到本地写完成和板端ACK后才显示开始确认。旧FS拒绝0x76时，App保留蓝牙和手机灯位，不显示练习已开始。

预备4拍后，绿灯持续提示当前音。弹错、不弹、提前按住均不会前进；必须在提示出现后重新按对，相同音要松键再按。CH376键盘、25K中转、触摸键分别跟踪按下状态，自动曲谱事件不参与判定。等键模式只提示当前绿灯，保留音高、次序，忽略原谱休止和时值，速度只影响预备拍。声音仍由你的键盘经原FM引擎产生。

“固定跟拍 · 练习节奏”按原时间轴前进，50%为75 BPM，75%为112.5 BPM，100%为150 BPM。开始时应用设置；运行中拖动不即时改变速度。手机断开后继续，S1停止，S4复位。

## 上传与自动演奏

连接页保留默认“138K · 跟灯与自动演奏”。展开“MIDI曲谱与自动演奏”，先停止上方练习，点“检测接口 / 容量”。收到0x55 ACK及带nonce的0x57能力回复后，按8192事件、16声部限制开放上传。载入内置曲谱或导入MIDI，使用默认115200逐帧确认，上传并等待数量/CRC确认，再点“FPGA开始演奏”。上传不会自动发声。

0x55/status1表示曲谱接口被拒绝；旧138K文件不支持本功能。App保留连接，不虚报上传成功。蓝牙READY只证明GATT和通知已打开，不能代替板端接口检测。上传区会就近显示按钮不可用的原因；超时日志包含命令、发送HEX、本地写状态。

曲谱在FPGA的8192×48bit同步RAM中保存{velocity,note,delay_ms}，RTL毫秒使能调度，原16复音、6算子FM引擎逐样本合成声音。无PCM、录音回放或手机流式演奏。MIDI保留原音高和节奏，《晴天》练习的移调、速度不影响自动演奏。超出25键映射的音仍可发声，但没有对应键位灯。自动演奏和《晴天》练习在板端互斥；S0不打断自动演奏，S1可停止两者。

STOP和自然结束安排CC64=0、CC123=0清理。已承诺的事件先完成握手，背压时不撤valid、不改data；清理随后优先发送。停止ACK表示已接受请求，不表示清理已经完成，过早再次PLAY可能被拒绝，稍后再试。释放尾音仍可衰减，同时弹奏的手动音也可能被All Notes Off释放。换曲/重播前先点停止。断开手机后继续；重连先检测、停止，再上传。RAM曲谱断电/复位丢失，v1中断需整曲重传。

FM音色和总音量继续用乐器屏幕；不接入App加法参数或旧0x56音量控制。可靠v2封包完整接收后拒绝，内部字节不会伪装成指引命令；能力回复不声明可靠v2。

## 协议

指引帧为A5 5A CMD D0..D7 XOR，D4..7=`GUID`。旧0x70..75含义保持：启停、定位灯、映射、清除、速度/预备拍/移调、只读检测。新增0x76：D0=0固定跟拍、1弹对再走，D1..3=0，仅停止且无自动播放/清理时允许。复位默认固定跟拍，旧App可继续使用；新版App开始前显式设置方式。

JDY曲谱命令使用相同12字节帧，不带GUID：

| 命令 | 数据/作用 |
|---|---|
| 0x55 | 全零，只读检测，成功F0 ACK |
| 0x57 | D0..3非零nonce，D4..7=0；F1返回nonce、8192、16声部、组8、flags=1、UART115200、v1 |
| 0x50 | D0..1数量1..8192，D2=1，其余0；开始即取消旧loaded状态 |
| 0x51 | D0..1连续索引；D2..5相对毫秒0..600000；D6音符0..127；D7力度0..127，0为NoteOff |
| 0x52 | D0..3为连续事件D2..7字节的IEEE CRC32；D4..5数量，D6=1，D7=0；数量/CRC全对才loaded |
| 0x53 | 全零，已loaded且无播放/练习/清理时开始 |
| 0x54 | 全零，停止并安排清理 |
| 0x56 | 当前FM JDY口拒绝；用乐器屏幕调音量 |

板载CH340仍用原FM协议。两个物理UART独立；JDY不转发到FM参数解析器。按键和曲谱公平仲裁，清理优先但不抢占已承诺的握手。

## 灯位导出与验收

“灯位校准 → 查看 / 导出灯位明细”支持离线查看、复制CSV和系统文件选择器保存CSV（UTF-8 BOM）。未校准项留空，灯0为第1颗。完整JSON仍要求25键无重复、无越界；保存失败原因显示在保存按钮旁。导出的是手机值，不是FPGA读回。

新FS默认映射仍为空；安装APK时沿用原包名、签名，手机灯位保留。不要卸载或清除数据；换FS后重新点开始/写入灯位。用户个人映射没有默认编入团队工程。

实板依次确认：原屏幕/触摸/键盘/FM声音；0x75和0x55有效回复；25键灯位；等键停留、错音不走、重复音松按；固定50%跟拍与预备拍；小曲上传/自动发声/停止；播放中S0不干扰而S1可停；断开手机继续；复位后重传/写入校准。ACK、仿真和生成FS均不代替实物验收。
