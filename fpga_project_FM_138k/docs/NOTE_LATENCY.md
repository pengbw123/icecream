## 测量定义

本模块不是物理按键到耳朵的完整自动测量。ACG720起点为板级USB/触屏/桥接仲裁接受LIVE NoteOn、进入输入FIFO之前；PC UART起点为接受事件时。包含板内FIFO与后续等待，不含键盘/触屏扫描、USB轮询及CH376解包前段。终点是最终音频超过32LSB后的第一帧I2S左声道最后一位采样沿。包括合成、效果、音量与I2S发送，不含DAC和模拟滤波；不对每个并发音符做因果归属。

SETUP→METERS：NOTE>I2S us NOW/MAX显示整数微秒最近/最大值；ONSET OK/TIMEOUT为成功和超时/模式中断数；ONSET SKIPPED是未满足条件的新NoteOn数量。原READY（音频tick到计算完成）和采样周期行被替换，旧MMIO0..17布局保留，新增18..23为最近时钟数、最大时钟数、成功数、超时数、跳过数、状态。CLEAR同时清理两组统计；清理中的测量取消。状态bit0等待起音、bit1已锁存候选帧、bit2安静资格、bit3测量允许、bit4活动声部为0、bit5当前幅度低于门限。

资格：连续32帧绝对值≤32且活跃声部为0；关闭ARP、SEQ、AI伴奏、AI旋律和练习模式；蓝牙曲谱播放/收尾期间也禁止测量，结束自动恢复。只弹一个LIVE音符，等待充分静音后再弹。连奏、和弦不作为可归属单音测量；等待期间再来NoteOn会取消当前测量。250ms未出现合格起音记超时。静音、低音量、慢起音会影响结果，数字值不得冒充纯算法耗时。

示波器：当前probe版本用P7-15输出标记，地夹接P7-12；CH1以上升沿单次触发。标记从合格数字事件出现后拉高，直到I2S完成、超时或取消。LED0为心跳；只有旧版本在LED0/M22输出标记。不要直接触碰BGA球。LED4额外汇总蓝牙回复队列溢出与旧桥接丢包，其余状态灯沿用现有定义。

CH2建议取ES8388耳机输出的一路模拟信号，使用3.5mm转接板，选择SETUP的HEADPHONE输出，耳机先拔下，示波器输入高阻。两通道共板GND。不要将普通接地探头的地夹接MAX98357的SPK-：那是桥接功放输出，不是地；测扬声器端须用合适的差分方法。本方案优先测耳机口。

设置快速起音、固定音色和力度、关闭全部效果，先调到波形清楚且无削顶。测CH1上升沿到CH2持续越过静音噪声门槛的时间，保存原始波形；写明起音阈值、输出口、音量、音符和负载。这个结果是“FPGA数字入口到模拟起音”；若要测真正物理按键到模拟输出，还需CH1改接键盘/传感器侧参考信号，或增加通道同时测两个起点。触屏首次接触无法从现有NoteOn标记倒推出扫描时间。

每种来源建议重复至少30次，记录最小/中位/最大值；可在显示与摄像头同时运行时重复单音测量。活跃声部为0的资格限制意味着本测量不能直接识别已有31声部中第32个音的独立模拟起音；满复音延迟需外部触发参考配合频率选择分析或另外的声部标签追踪，不能从本统计推断。测带效果/慢包络的听觉起音时，要另列其有意延时，不能和干声引擎延迟混报。本轮没有预先填写任何实测数值。

外部MIDI多频测试的可选方案：选择ALGO32（六算子均为载波），仅开启一个正弦算子，反馈0、关闭LFO/滑音和所有效果，快速起音、稳定保持包络。依次保持4/8/16/32个不同MIDI音符，停止时释放全部音符；由PC/键盘发送MIDI和弦时，音频仍全部由FPGA实时生成，不是播放录音。可选4音C4/E4/G4/C5、32音MIDI48..79。该低音区序列适合外部足够长FFT（如32768点）及窗函数，频率轴按采集设备实际采样率标定。屏幕原对数频段柱图不适合精确数峰；新版LIN FFT和板载MIDI96..127序列用于屏幕32峰演示，二者不能混用期望频率。

演示时同时显示活跃声部数、deadline/lost_ticks/drop计数和频谱：加一个音应多一个基频峰，释放后对应峰消失；不能把单个FM音色的谐波峰算成多个独立声部。32条正弦证明32个独立可闻声部，不能据此证明192个可闻算子。当前板载模式由首页VOICES按S0启动MIDI96..127，S0或S1停止；上段MIDI48..79是外部高分辨率FFT的可选方案，不能与板载期望频率混用。

代码验证：精确I2S最后位终点、输入VALID背压去重、安静门限、超时、重叠音符取消、清理和快照已有专项仿真；I2S输出选择及真实AI/FM32/I2S回归通过。完整构建及当前下载状态以发布记录为准，尚未实机测量。

## 现可使用的现场多音序列

已提供tools/multitone_probe.py，走现有PC UART自定义MIDI协议（115200），不是将PC USB插入板上的USB Host。关闭其他占用串口的软件。先手动准备单载波、ratio=1的正弦音色，关闭FX/ARP/SEQ/AI，保持包络稳定，再执行：

```
python tools/multitone_probe.py --voices 32
python tools/multitone_probe.py --voices 32 --port COM6 --prepared-sine --seconds 10
```

第一条只打印期望音符及频率，不连接硬件；第二条中的COM6须换成实际板卡PC串口。需要pyserial。分别使用4、8、16、32做四档测试；先调低音量、观察削顶。发送结束或Ctrl+C时脚本发送NoteOff与CC123清理。串口断开、断电或强制杀进程时finally不能保证送达，重连后需手动全停。全部音符到齐需串口传输时间，等稳定后再数峰；此脚本不能把PC调用时间当硬件起始时间。

注意：最近值和最大值仅在成功测量时更新。超时或跳过时会保留旧值，必须确认OK计数随本次触发增加。若要把串口解码也纳入测量，可将CH1改为PC UART RX的电气信号，发送孤立的NoteOn协议包，以首字节起始位为起点，再测CH2模拟输出；不要把操作系统write调用时刻当作串口实际发送时刻。
