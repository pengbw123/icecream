# 2026-10-30 FPGA灰度手势识别

## 实现与接口

生产摄像头RGB565字节拼接后，在与RGB332预览相同的裁剪/降采样位置输出原16位像素抽头。经过整帧几何校验和预热，中央96x96区域取32x32灰度，经单银行跨时钟邮箱送到50MHz纯RTL CNN。不通过软核运行图像算法。

网络结构：32x32 u8 → valid 3x3步长2卷积4通道（15x15x4）→截断ReLU到0..127 →3x3最大池化（5x5x4）→100项全连接→4个有符号分数。436个INT8权重、8个INT32偏置，单MAC复用。卷积累加算术右移7位，全连接输出保留整数分数。单次18909时钟，50MHz下378.18微秒；不含整帧采集、邮箱重放、投票等待和发声延迟。

四类为FIST、PALM、V SIGN、OTHER；OTHER不允许投票或音乐命令。对四类一起排名，第一第二名差至少2048才能通过；它是工程分差门槛，不是概率。沿用3/5首次确认、4/5切换、连续拒识/断流退出跟踪及手动优先。BASIC/PERFORM及其默认OFF不变。

分类器使用连续灰度值，不依赖黑白轮廓。位置控制另用低于帧平均亮度8级的取样点建立辅助16x16轮廓，该轮廓不影响CNN分类。复杂背景下这个重心也可能偏移。

## HDMI与菜单

左侧预览显示真正进入CNN的32x32输入中奇数行/奇数列的16x16灰度取样，每格8倍放大；这是降采样预览，不是完整32x32画面。连续灰度帧与结果包一起锁存，2372位跨域持有包只在视频消隐更新。E显示帧平均灰度0..255，已不再代表旧版前景能量；M仍为分差。OTHER显示为拒识原因。RGB页面RAW可以显示OTHER，稳定类别仍限三种有效手势。

## 训练、验证边界

本机CPU/NumPy训练，种子3010720。继续使用Laurence Moroney白背景CGI石头剪刀布数据（CC BY 2.0，来源和原ZIP散列见旧DATASET说明及training_report）。2160训练/360验证手势，按既有文件名序列隔离。另生成720训练、180验证、180测试合成OTHER，包括平面、渐变、噪声、圆斑、格纹。训练增强包含大小/平移/旋转、对比度、曝光和明暗渐变；真实杂乱背景未覆盖。

训练160轮，仅按隔离验证集选择第48轮。验证95.93%；独立公开372张手势330张正确（88.71%）；180张合成OTHER中171张归OTHER（95%）。总体501/552正确。公开测试已多轮查看，不能作为以后完全未知的盲测；没有使用测试样本做梯度训练或选轮次。

这些结果不能等同实机准确率，也不保证任意背景下手部定位、肤色/姿态泛化或所有陌生物体的拒识。固定中央ROI仍要求手位于框内。后续实机应先开RECOGNITION、关CONTROL，对比RAW/STABLE及灰度预览。

离线压力测试详见assets/gesture_gray_cnn/stress.json：公开手势正确且通过门槛为原图300/372、曝光70%298、曝光50%277、渐变照明307、噪声299；向右平移3个灰度像素时仅224/372，说明位置鲁棒性仍有限。原始180个合成OTHER中有6个错误通过有效手势门槛；“第四类”不等于零误触发。没有根据这些测试结果回调门槛或重新选训练轮次。

## 复现

```
python tools/gesture/train_gray_cnn.py --epochs 160
python tools/gesture/check_gray_cnn.py
./sim/run_gray_checks.ps1 -IverilogDirectory <bin> -Python <python>
./sim/run_gesture_checks.ps1 -IverilogDirectory <bin> -Python <python>
./sim/run_camera_checks.ps1 -IverilogDirectory <bin> -Python <python>
```

模型、552组输入/2208项预期分数及报告在src/generated/gesture_gray。gray_reference为训练与RTL共用的预处理参考。旧二值模型和旧识别器通过GRAY=0保留回归，生产摄像头选择GRAY=1。

最终资源、时序、位流校验及回退以本轮release记录为准。独立灰度前端的1块BSRAM不能代表整个CNN加预览的资源消耗；没有通过完整构建时不能将其当作可烧录版本。
