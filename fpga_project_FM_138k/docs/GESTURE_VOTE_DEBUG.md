# 手势稳定判定与真实网络输入预览

## 时间滤波

生产控制器开启TEMPORAL：最近5个推理结果中，首次确认需要当前类别至少3票；已确认后切换另一类别需要当前类别至少4票。拒识结果占用窗口但不投票。偶发不同类别或拒识不会立刻更改稳定标签。

连续3个拒识结果退出跟踪并重新允许同一手势；连续5个不匹配当前稳定类别的结果也退出跟踪，但不因这类模糊结果自动重复触发原手势。1秒没有新结果则清除跟踪、投票历史和未消费命令。帧数不是固定毫秒数，实际延迟取决于摄像头与推理结果帧率。

音乐控制仍需显式打开，且仅作用于COMPOSER；持续保持同一手势只发一次命令。手动触屏/打击垫命令优先并清除旧投票，保持张掌不会立刻撤销手动STOP；开始控制时也不重放已保持的手势。旧连续帧判定作为TEMPORAL=0保留用于对照回归。

时间滤波只改善抖动和触发稳定性，不能纠正持续的错误分类。本轮模型权重、分割门槛、摄像头配置及音频固件不变。

## HDMI输入预览

开启RECOGNITION后，HDMI左上角x0..127、y32..159为16x16真实网络输入的8倍放大图，下面标注NN INPUT。白格为前景（网络输入127），黑格为背景（输入0）；外沿只覆盖1个显示像素，不抹掉外围特征格。该窗口位于中央识别框之外，不遮挡手部区域。

它来自实际写入MLP的256个特征，绝不是另外重算的示意图。控制器将轮廓和同一推理结果一起锁存，通过324位持有/请求应答跨时钟传输；只在HDMI垂直消隐更新显示，避免撕裂。显示有约一个视频帧的额外等待，音乐控制不经过这个显示通道。

保留原E（前景能量）和M（分差），底部右侧增加原因：

| 标记 | 含义 |
|---|---|
| CAMERA | 相机未就绪/故障 |
| NO FRAME | 尚无新推理结果或已过期 |
| EMPTY | 前景少于7格，手没进入或轮廓丢失 |
| FILL | 前景超过192格，背景混入或手过大 |
| BORDER | 周边前景超过24格，检查手是否出框/背景是否干净 |
| NOISE | 水平垂直边缘跳变超过96次，轮廓过碎；不等于已经证实传感器噪声 |
| LOW GAP | 分类第一、第二名分差不足 |
| VOTING | 当前帧通过，但还没形成稳定投票 |
| HOLD | 当前帧类别与稳定标签不同，暂时保留稳定标签 |
| STABLE | 当前通过且与稳定标签一致 |

若彩色画面正常、黑白图却一片白/黑，优先检查分割；黑白图能看出手形而RAW类别仍错误，重点是模型/数据；RAW偶有跳变但STABLE持续正确，说明滤波有效。关闭识别后恢复原来的完整摄像头诊断显示。

## 验证与发布

投票、手动优先、背压、超时/重启、轮廓逐格比对、拒识原因、324位跨域和全帧显示一致性均有专项测试。具体构建时间、资源、时序、下载文件与回退位置以本轮release记录为准；没有自动烧录，也不能把仿真通过当成真实手势准确率。
