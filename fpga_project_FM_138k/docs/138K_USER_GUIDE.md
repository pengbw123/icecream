# ACG720-138K FM 合成器使用说明

适用版本：2026-10-23 RGB/HDMI/ES8388 版。当前为 16 复音、6 算子、32 个 ROM1A 预设；本次耳机驱动及效果器改动尚待用户实板验证。本文说明的是当前代码已经具备的功能，不把后续规划当成已完成。

## 1. 需要准备什么

首次下载到看到现象、25K和138K程序固化的详细流程请看 [下载与固化步骤](PROGRAM_AND_FLASH.md)。

- ACG720-138K 开发板及下载器、电源。
- TFT V3.0 800×480 RGB565 电容触摸屏，与板上 J1 40pin FPC 配套的排线。
- MAX98357 I2S 功放和扬声器（沿用之前的模块），或耳机接板载 OUT1。2026-10-23 版本已加入 ES8388 驱动，与功放播放同一音频、共用主音量；模拟输出尚待实机验收，见 [耳机监听说明](ES8388_AUDIO.md)。
- 可选：Primer25K + Dock + USB MIDI 键盘，用作临时 USB 主机中转。
- 可选：25 颗 WS2812 灯条、合适的独立 5V 电源、3.3V→5V 电平转换器。
- 电脑通过板载 CH340 串口编辑或演奏；不接电脑也可使用触摸琴键。

138K 板上 CH340 和 FX2 USB 通信口都是面向电脑的设备接口，不是键盘的 USB 主机。CH376S 模块的驱动尚未加入。

## 2. 断电接线

GPIO0 Bank 电压设为 **3.3V**，接线前核对实板跳线。不能把 5V 逻辑直接送入 FPGA IO。

| 外设信号 | 板上接口 | FPGA 管脚 |
|---|---|---|
| MAX98357 BCLK | P7-1 | A13 |
| MAX98357 LRC / LRCLK | P7-2 | A14 |
| MAX98357 DIN | P7-3 | A15 |
| MIDI 中转串口 RX | P7-4 | A16 |
| WS2812 DIN（经电平转换） | P7-6 | A19 |
| 公共地 | P7-12 或 P7-28 | GND |
| RGB屏 + 触摸 | J1，40pin FPC | 已在 acg720_rgb.cst 约束 |

FPC 必须确认 1 脚位置、触点朝向及同向/异向排线，断电插拔，不可只凭“40pin 能插进去”认定方向正确。
功放按模块规格供电，和 FPGA 共地；扬声器接功放 SPK+/SPK-，不要把任一扬声器输出当 GND。
灯条不能从 FPGA GPIO 取电，建议独立 5V 供电并共地；建议使用 74AHCT125 等合适电平转换器，串接数据电阻、按灯条要求去耦。不要直接把两块板的 5V 相连。

## 3. 烧录哪个文件

138K 本次使用：**fpga_project_FM_138k/impl/pnr/fm_138k_rgb_hdmi.fs**（2026-10-23 14:39，RGB 与 HDMI 同时输出，含板载耳机监听）。
旧的 fm_138k_rgb.fs 尚未重建，不能用于验证本次 ES8388 功能。
Primer25K 中转使用：**fpga_midi_bridge_25k/impl/pnr/midi_bridge_25k.fs**。
复制目录里可能仍留有 fpga_project.fs，它不是本版 RGB 输出文件。下载时先核对路径、器件和文件修改时间。

使用 Gowin Programmer 的 SRAM 下载适合先测试，重新断电后需要重新下载；要上电自动运行，需按开发板 Flash 型号和官方流程烧写非易失存储，不能把 SRAM 下载误认为已保存到 Flash。

首次建议只接 138K、屏幕和音频，不接灯条与中转。下载后按 S4 复位，触摸控制器约 177ms 复位同步，随后固件探测。

## 4. 屏幕怎样操作

- 顶部显示音色名、P（预设编号）、V（活动声部数）、A（算法编号）。P 显示 1～32，而 CC27 使用 0～31。
- 波形区显示输出 PCM 的一段快照，不是 FFT，也不是采样回放波表。
- 六条柱显示六算子的包络状态；它们不是六个频段的真实测量频谱。
- 峰值表显示输出幅度，削波提示表示达到接近满幅的区域；不代表已经测量功放的模拟失真。
- 底部 25 键默认 C3～C5（MIDI48～72）。可同时识别最多 5 个触点，黑键优先命中。
- PRESET 左/右：上一个/下一个预设，首尾循环。
- VOLUME 左/右：总音量减/加 5，范围 0～127。按住不连发，需要抬手再按。
- OCTAVE 左/右：改变屏幕琴键音区，范围 -3～+3。会释放当前屏幕按键，不改变外接 MIDI 键盘自己的八度设置。
- PANIC：释放屏幕按键，关闭延音踏板状态并发送 All Notes Off。音色仍按释放段收尾，不是强制截断所有 PCM。
- TOUCH OK 代表已识别控制器；仍需触摸琴键确认坐标和触点上报真正正常。
- VIEW 左侧WAVE显示原有波形，右侧XY显示纯RTL延迟李萨如图。XY DELAY的±以1采样点调节，1～96，默认24。一个采样点为20.48us，默认延迟0.49152ms。这里的延迟只影响图像，不影响听到的声音。

XY用X=s[n]、Y=s[n-delay]构图，不是FFT，也不是左右声道相关仪。当前左右输出相同，直接用L/R只会得到斜线，所以采用延迟坐标；单音可能形成椭圆，多音和FM音色可出现复杂轨迹。音量很小时轨迹也会变小，静音时通常为中心点。

同一琴键被两个触点按住时，只产生一次 Note On，最后一个触点离开才 Note Off。触摸力度固定 100，本版没有面积模拟压力。

屏幕预设名来自 ROM1A 名称表。电脑发送自定义音色后，这个名字不能当作自定义文件名或参数相同的保证；当前没有自定义名称上传菜单。

## 5. MIDI 键盘和 25K 中转

1. 向独立 Primer25K 中转工程下载 midi_bridge_25k.fs，键盘插 Dock 的 USB-A。
2. Dock J3-15（F1，TX）连接 138K P7-4（A16，RX），再连接公共地。两板各自供电。
3. 此链路为 **1 Mbaud / 8N1**，不是原来调试串口的 115200。当前只需要 TX→RX 单向数据，不交叉接两根 TX。
4. 25K 调试串口仍为 C3 TX、115200/8N1，可看 USB 枚举日志。

| 键盘操作 | 当前功能 |
|---|---|
| 琴键 + 力度 | Note On/Off，音高不限于当前25键音区 |
| MODE（CC20） | 总音量 0～127；0 静音 |
| TRANSPOSE（CC27） | 数值0～31直接选择32预设；32～127忽略 |
| PITCH 滑条 | 14bit 弯音 |
| MOD（CC1） | 颤音深度 |
| RATE（CC26） | 颤音速度 |
| 踏板 CC64 | ≥64踩下，松键暂不释放；<64抬起，已松开的键进入释放段 |

本版为原声对照模式，Chorus/Reverb 等效果器旁路；OCT/GATE/SWING/TEMPO 旋钮即使发出原有 CC，也不会产生对应效果器听感变化。LATCH 对应的 Portamento 还不是完整 Dexed 兼容实现。
键盘通道0的力度沿用 0x00→0、0x5A及以上→127 的映射，只在25K中转做一次；打击垫等其他通道不缩放。

## 6. WS2812 指示

第1～25颗灯固定对应 MIDI48～72（C3～C5），不随屏幕八度切换。超出这段的音可以发声，但不会点亮这25灯。
弱力度偏青绿，强力度偏橙红。灯亮灭表示按键事件，不表示尾音：踩着延音踏板松键时声音可继续，但灯会熄灭。
当前没有为每个 MIDI 通道分别维护同音键的灯计数，也不是多源同音触点的归属管理系统。调试时建议先只用一个演奏来源。

## 7. 电脑编辑和演奏

连接板载 CH340，设备管理器确认 COM 号。接收参数均为 **115200 / 8N1**。

- FM 编辑器：tools/launchers/run_fm_editor.bat，载入 .syx 或 FM JSON，选择串口发送完整音色，可用 C3/C4 试听按钮。
- 自动演奏：tools/launchers/run_uart_midi_player.bat，选择 MIDI 文件和 COM 口。
- 首次使用先运行 tools/launchers/install_python_requirements.bat，要求可用的较新 Python；旧 Python 3.7 不适合当前工具的语法与类型标注。
- 同一个 COM 口同一时刻只给一个程序使用。串口助手、FM编辑器、自动演奏软件之间切换前先断开/关闭前一个，不要重复抢占。
- 看诊断日志时用串口助手；操作编辑器时先关闭助手。普通串口助手直接发送原始三字节 MIDI 不是本项目的打包演奏协议。

当前电脑端 UI 的标题可能仍写 Primer25K，它沿用相同协议，不表示需要接25K的串口。
发送到运行中 RAM 的编辑参数不会自动存入 Flash；复位/重新下载回到内置默认预设0（BRASS 1）、音量96、屏幕八度0。SD卡保存还没实现。

## 8. 状态灯与故障排查

| 板载 LED | 含义 |
|---|---|
| LED0 | 50MHz 域心跳 |
| LED1 | 视频 PLL 锁定 |
| LED2 | 最近约100ms收到已接受的MIDI事件 |
| LED3 | 触摸控制器被识别 |
| LED4 | 专用中转口出现事件来不及接收的丢弃计数，复位清除 |

**黑屏**：确认下载 fm_138k_rgb.fs；确认器件B版、顶层top_138k；检查 CPU/SSPI 复用脚已设为GPIO；确认LED1、FPC方向、背光和供电。不要通过乱改触摸配置表解决显示黑屏。

**有图无触摸**：用 CH340 查看启动和 GT 日志。正常有 ACG720 138K FM RGB/GT UI ready、GT found addr、分辨率及 DIRECT/SWAP_XY。识别不到时先检查FPC与复位/INT/I2C。识别到但始终没触点时保存完整日志，不强行覆盖控制器配置；历史故障与这些初始化细节有关。

**能按亮但没声音**：先按VOLUME加几次，选已知预设如E.PIANO1，检查P7三根I2S和公共地、MAX供电/使能、扬声器。板载耳机需接 OUT1，并使用包含 ES8388 驱动的新位流，上电等待约一秒。按键灯不等于音频物理链路正常。

**PC可演奏、外接键盘无反应**：检查25K枚举日志、F1→A16及共地，确认25K烧的是中转版本；不要把138K的USB设备口当主机。

**画面稳定但触摸位置不准**：记录实际面板分辨率和GT打印的DIRECT/SWAP_XY；本版做了横竖坐标交换与比例缩放，但不自动判断镜像方向。

**串口无法打开/突然断开**：关闭其他占口工具；检查设备管理器COM号是否变化及线缆接触。蓝屏属于驱动/系统层故障，FPGA不能保证修复，保留系统故障信息并更换可靠线缆/驱动排查。

**声音按住仍会衰减**：FM每个算子有自己的四段EG。钢琴类音色按住也可能衰减至很低，不应把所有预设强制改成恒定响度。

## 9. 重新编译与回归

在工程根目录运行 Gowin gw_sh.exe build_cli.tcl；项目顶层为top_138k、器件GW5AT-LV138PG484AC1/I0-B。
改触摸 C 固件后先运行 src/ui_firmware/build_firmware.ps1 -Zig <zig.exe绝对路径>，再综合。firmware.hex 已随源码保存，不修改固件时不用安装交叉编译器。

已安装 Icarus 时运行 sim/run_checks.ps1；不在PATH时加 -IverilogDirectory <iverilog/bin绝对路径>。测试覆盖串口半帧恢复、WS2812、触摸真实固件和RGB扫描。
Icarus可能提示8KiB指令ROM读取16KiB镜像时文件字数较多；指令使用前8KiB、数据使用完整镜像，实际固件生成脚本会检查代码没有超限，此警告不是触摸自检失败。

上板验证仍是必要步骤。仿真 I2C 模型不会覆盖真实GT的电气、排线和所有固件版本；时序通过也不等于完整DX7音色PCM逐位一致。

## 10. 资源余量怎样理解

本次修复后已重新综合、布局布线：

| 资源 | 已用 / 总量 | 剩余 |
|---|---:|---:|
| Logic | 17657 / 138240 | 120583，约87% |
| CLS | 13422 / 69120 | 55698，约81% |
| BSRAM | 116 / 340 | 224块，约66% |
| DSP | 23.5 / 298 | 274.5，约92% |
| PLL | 1 / 12 | 11 |

Logic与CLS是不同统计口径，不要相加成“总占用”。主时钟50MHz，当前报告Fmax52.782MHz；像素时钟33.333MHz，报告Fmax43.544MHz；两域setup/hold TNS均0。数据来自2026-10-19 21:54构建（含128KiB软核数据存储），50MHz域余量仍不算宽裕；硬件容量空余很多不代表声部数可直接扩大八倍。

音频每样点只有1024个50MHz时钟周期。6算子×16复音为96个逻辑算子，由共享计算通路调度，不是96套完整独立硬件。扩到32/48/64复音须核算每帧排程、流水线依赖和存储端口，再重新验证时序/声音；本次未承诺已实现这些复音数。

剩余284块18Kbit BSRAM约639KiB，单张800×480 RGB565完整帧约750KiB，因此不能仅凭“BSRAM空闲很多”就加入完整帧缓存。目前直接RTL绘图无需完整帧缓存；未来复杂GUI/大图片若需要整帧缓存，应评估DDR3，而非挤掉音源状态存储。

## 11. 后续怎么做更合适

建议按以下顺序推进，避免同时改音色、USB、屏幕而失去对照：

1. **先实板稳定**：屏幕色彩/坐标、触摸滑动与松键、复位、长时间演奏、断插MIDI、灯条供电逐项验证。确认没有横条纹和卡音，再扩功能。
2. **音色还原优先**：板端PCM采集配合Dexed同音色/音高/力度/按住时间对比，定位AMS量化、增益/乘法精度、反馈截断溢出等剩余误差。显示迁移不能替代此验证。
3. **独立USB主机接入**：CH376S到货后验证枚举和USB-MIDI端点，再替代25K中转；保留中转作可靠对照。模块能供电/枚举不等于驱动已经能识别所有键盘。
4. **控制链路加固**：按实际压力测试结果增加事件FIFO、输入来源归属、串口统计/更强校验；避免触摸和物理键盘同音时互相松键。
5. **扩复音/精度**：先评估32复音排程和位宽，必要时增加计算通道或存储带宽，而不是只升主频。每次保留前版PCM和时序报告作对照。
6. **补齐屏幕菜单**：音色浏览列表、6算子算法连线图、算子四段EG曲线、参数页；触摸选中参数，MIDI旋钮细调，保留电脑编辑器作深度编辑工具。
7. **视觉与效果**：波形与延迟李萨如已加入；后续FFT需要另加采样窗/FFT/幅度处理。再恢复混响、合唱及效果器旁路对照，不用参数重建的柱状图冒充输出实测频谱。
8. **产品化**：板载ES8388模拟输出实机验收、预设掉电保存/SD卡、统一供电与外壳。ES8388驱动已接入，其余仍为后续工作。

## 12. 最终成品可以是什么形态

建议最终做成“不依赖电脑也能演奏、电脑可选辅助”的桌面FM合成器：

- 外接25键MIDI键盘负责演奏、弯音、颤音和旋钮，延音踏板负责自然延长音符。
- 138K是声音和视觉的中心：6算子FM、经典音色库、可保存的自定义音色、可切换效果器；最终复音数按验证结果确定。
- RGB触摸屏提供三类页面：**演奏页**（音色/音量/键盘/状态）、**编辑页**（算法图/算子EG/参数）、**视觉页**（实际PCM波形/李萨如/后续FFT）。视觉绘制保留RTL实现，软核只管理输入和参数。
- 25灯条负责直观按键/力度反馈；固定C3～C5是当前规则，未来若要跟随物理键盘八度，应明确新增映射策略。
- USB主机模块到位后不再依赖25K中转；MAX98357可继续作为第一版音频输出，板载Codec通过验证后再收拢模块。
- 电脑只负责高级音色编辑、音色备份和Dexed数字对比，不再是日常选音色和调音量的必需品。

演示可按“选EPiano→弹奏/力度→踩踏板→换Brass并弯音/颤音→屏幕查看包络与波形→切换效果器→展示同条件Dexed数字对比”的顺序。只有完成并实测的环节才列入正式演示；当前先演示预设、触摸、波形、灯条和已有MIDI演奏。
