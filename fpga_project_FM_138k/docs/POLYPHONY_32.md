# 32 复音扩容（2026-10-24）

生产配置由 16×6 改为 **32×6 FM 运算器状态**，192 个独立槽位；采样率仍为 48.828125 kHz。
单音滑音仍为单音模式。128 个预设、效果链与输出音量标度保持原有定义。

## 实现

- `top_138k.v`、`top_138k_hdmi.v` 的 `AUDIO_VOICES=32` 同时传给音频和 UI。
  `top.v` 的 `FM_VOICE_COUNT` 默认 32，并传给 FM 引擎及性能监测器。
- 核心模块 `fm_poly_synth` 本身保留 16 的默认参数，供独立测试与复用；生产顶层显式覆盖为 32。
- 运算器读写地址宽度由 `$clog2(VOICE_COUNT*6)` 决定；32 声部为 8 位，
  去除原有 `[6:0]` 截断，覆盖 0..191。相位、包络、增益插值和滑音存储共享相同槽号。
- 声部索引由 `$clog2(VOICE_COUNT)` 决定，活跃声部计数通路扩为 8 位。
  计数使用平衡加法树，避免原来逐声部串联累加随扩容拉长。
- IDLE 中待处理采样优先于待处理 MIDI。已开始的音符初始化仍完整结束，再处理采样；
  连续 MIDI 输入不会永久占据 IDLE 调度机会。MIDI 仍通过 ready/valid 背压等待。
- 混音继续使用有符号 40 位累加器。32 路有符号 32 位输出求和需要 37 位，仍有余量；
  不通过除以声部容量降低单音响度，最终软限幅规则保持一致。
- 性能页容量来自实际参数。RGB、旧 SPI 状态显示接口与顶层监测接口均同步加宽。

## UI 寄存器兼容

`UI[4]` 原音量、音色和算法位域保留：

- `[6:0]` 主音量。
- `[11:7]` 音色低 5 位。
- `[16:12]` 算法。
- `[21:17]` 活跃声部低 5 位。
- `[23:22]` 音色高 2 位。
- **`[26:24]` 活跃声部高 3 位**，此前保留。

新增只读 **UI[59] = 声部容量**。固件用 `status_voices()` 解码计数，
标题及性能页显示容量 32，不再把满载误显示为 0；音色 128 的高位不受影响。

## 验证

已通过的针对性仿真：

1. 192 个槽位全部初始化且相位推进；高槽位写入不污染 voice 0；活跃计数覆盖 31→32。
2. 32 声部踏板保持、松踏板释放、CC120 全静音；满载后抢音。
3. 连续 256 次非零 Note On、反复音高、1024-clock 周期采样：deadline/lost tick 均为 0。
   该场景最大 FM 响应耗时 **457 clocks（9.14 μs）**。
4. 满载无事件阻塞：render=**394 clocks（7.88 μs）**，response=395 clocks。
5. 16/32 两种配置同时输入相同 16 音和弦：32 种算法、最大反馈、4096 帧逐样本一致，
   其中 3874 帧非零，排除纯静音的无效比较。
6. 32 声部配置下原单音滑音测试通过：相位/包络连续、双向滑音、终点、最后按键优先、踏板及恢复多音。
7. 真实 RV32I + Goodix 固件：标题 31/32 与 32/32、音色 128 高位隔离、性能页容量 32；
   截图 `tmp/poly32_performance_preview.png` 为测试模型数值，不是实机性能读数。

测试入口 `sim/run_checks.ps1` 已登记 `+poly32`、32 声部 `+metrics/+legato`、16/32 PCM 对比与 UI 场景。
构建/资源/时序结果见 AI_HANDOFF.md 最新发布记录；未实机烧录之前不能声称实机通过。

## 实机验证

双屏发布位流：`impl/pnr/fm_138k_rgb_hdmi.fs`（2026-10-24 15:34:07），四域时序通过。
最终资源 Logic 48,036（35%）、FF 25,517（19%）、BSRAM 314/340、DSP 65/298；
相比性能监测版增加 6312 个逻辑单元、3852 个寄存器，片上 RAM/DSP 数量不变。
主域 Fmax 50.005 MHz，满足 50 MHz 约束但余量很小。尚未实机烧录验证。

1. 烧录双屏新版，确认标题分母与 PERFORMANCE 容量均为 32，音色名称正确。
2. 清零性能计数，踩延音并连续弹和弦，观察活跃声部能超过 16、到达 32。
3. 到达 32 后继续弹奏，出现抢音计数属于正常满载行为；无挂音、毛刺或丢失松键。
4. 开启所需效果与 FFT，同时运行琶音器/音序器；三个错误计数应保持 0。
5. 松开踏板后观察尾音正常回收；验证滑音模式仍只有一个声部。

32 声部为配置容量，192 是运算器槽位数；不能直接把这些值声称为比赛时刻的“可闻独立振荡器数”。
本次只完成 32 复音目标，64 复音仍需独立检查存储、调度和时序。
