# 灰度光照自适应及USB键盘延迟测量

## 灰度输入

识别区域仍是160×120预览中央96×96，取32×32灰度采样。新增gesture_gray_adapt整帧预处理：四角2×2最大值估计白背景，双线性插值背景平面；全帧最暗值估计黑端；背景减去像素得到暗度，按背景与黑端的跨度拉伸。跨度至少32，增益有限；截断到0..255。保留灰度，不二值化。无需用户手动设置阈值。

Python gray_adapt.py与RTL使用相同的整数除法/移位/截断，训练增强后再执行相同预处理。正常推理也必须先调用adapt_gray；直接给CNN送未经处理的灰度不再符合模型。HDMI小预览保留原始灰度以排查曝光，CNN实际使用自适应灰度；不要把预览误认为网络最终输入。FRAMES在整条处理完成后增加。

仍假设角落主要是明亮背景、手较暗，不适用于任意杂乱背景、反向极性或角落被手完全遮住。曝光导致的信息丢失无法恢复。没有自动手部定位/缩放。实际相机识别效果须重新验收。

重新训练160轮，按验证集选择第114轮。公开测试集手势312/372（83.87%）、合成OTHER171/180；真实相机准确率未知。原始集正确且通过拒识304，旧模型300；半曝光304对277，低对比302对214，不均匀光照297对289。测试集变换仅作报告，未用于选择模型或调门限。新模型部分原始分类下降，合成负样本误接受也有增加，不能笼统宣称更准。

新增数据RAM及乘法资源以最终PnR报告为准；不删除模块，不降低音频或相机时钟要求。默认继续灰度；顶层GESTURE_GRAY=0可在未来构建切回原二值背景补偿方案。

## 音符到I2S脉冲

板级USB/桥接/屏幕三路仲裁接受事件、进入输入FIFO时作为起点，剥离USB cable/CIN传输头，所有MIDI通道NoteOn使用同一规则。PC UART参数口保留单独已接受事件作为起点。终点仍为实际起音I2S左声道最后一位采样沿。LED0/M22高电平宽度与板内计数一致，未增加第二个标记引脚，不测手势延迟。

脉冲包含输入FIFO、后续仲裁、合成/效果/音量和I2S串行输出；不含键盘扫描、USB轮询/CH376解包前段、DAC及模拟输出。因此不能只凭该脉冲声称题目完整端到端小于5ms。完整指标需示波器CH1测输入标记、CH2测模拟输出，或从更上游输入参考点起测。不能将普通地夹接MAX98357 SPK-。

资格仍为输出安静至少32采样、活动声部为0、无ARP/SEQ/AI/练习/蓝牙曲谱；250ms起音超时。连奏和和弦不做因果归属。METERS增加MODE BLOCKED/WAIT VOICES=0/WAIT QUIET/READY: ONE NOTE/MEASURING，区分读数不更新原因。NOTE>I2S为微秒，1000us=1ms。CLEAR清除最大值/计数及在途测量。

此次把起点前移并为真实USB解码、三路仲裁、FIFO到FM32/I2S建立端到端回归。原先实机USB不触发的唯一原因未能在旧代码中复现，不能把“已验证新路径”写成已找到旧版确定根因。
