## 本次发现并处理

1. 同键多触点：旧逻辑按触点单独发 Note On/Off。两个手指按同一琴键时，一个离开就可能停止另一手指还按着的音。改为整帧新旧音符集合比较，重叠触点共享一次按下，最后一个离开才释放；轨迹ID交换不重触发。
2. I2C 半更新：旧逻辑可能在清就绪位失败前已经改变音符和菜单状态。现先读完所有点并确认清就绪成功，再提交该帧。异常触点数也尝试清就绪，避免一直读取同一坏帧。
3. 错误累计：原来正常“无新帧”不会归零错误计数，稀疏I2C错误会最终误判失联。现只有连续40次读写失败才触发释放和重新探测；正常无新帧继续保留按键。
4. 串口半帧：中转接收器新增2ms字节间超时，发送板复位/线缆重连后的残缺帧不会长期占据解析状态。正常一字节10us，完整帧120us。不能因此保证任意噪声下零丢包，也不能恢复已经丢失的松键事件。
5. 增加 sim/run_checks.ps1，统一运行事件链路/WS2812、真实UI固件触摸、RGB扫描回归。
6. 原移植草案标记为历史规划，避免误以为已使用DDR/HDMI；独立使用手册说明实际接线、控制功能和限制。

## 明确仍有的限制

- 尚未实板验证138K屏幕/触摸。GT原始配置为空时不会猜测写入配置，需按实际面板专门诊断。
- 多来源或多MIDI通道的同音按键未做完整归属/引用计数；屏幕+外部键盘同时弹同一音时，Note Off仍可能释放相同音高的其他声部。现在不要宣称多输入完全隔离。
- 中转UART无反向流控和CRC重传，事件缓存只有一个待交付槽；丢弃计数由LED4提示。正常链路事件速率远低于音源吞吐，但仍需长时上板压力测试。后续可加FIFO/更强帧校验，不应假装本次已实现。
- RGB多bit监测数据采用双级采样后逐帧锁存，适合观感反馈，不是精确同步测量接口；关键波形数据使用银行握手。
- 视频PLL失锁时缓存所有权的风险已在随后的XY版修复：采集和显示握手两侧一起复位、分别同步释放，新增失锁再锁定仿真通过。真实板上的电源/时钟异常仍需现场验证。
- 不能由本次IO仿真推出Dexed完整PCM逐位一致，PCM采集和音色数值对照仍在后续任务中。
