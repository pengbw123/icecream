# OV5640稳定采集：第一阶段

本阶段用HDMI1（J6）显示摄像头，RGB屏继续显示合成器菜单；原HDMI波形/李萨如/频谱/辅助演奏画面暂不实例化，源码保留。尚未加入手势识别或改变旋律控制。

## 接线与画面

- 小梅哥ACM5640-V5接板上P4的2×10摄像头接口，按模块与板卡的1脚方向对齐。断电插拔。板上提供3.3V，PWDN已有下拉，不另接5V。
- D0..7依次J5/H2/G1/J2/F1/G2/E2/E1，PCLK B1，HREF A1，VSYNC B2，XCLK M17，RESET N20，SCL M20，SDA L18。依据板卡原理图第1/2/11页，与当前引脚无冲突。
- 复用现有HDMI PLL的25MHz作XCLK，不新增PLL。传感器320×240 RGB565，隔行隔列抽取为160×120 RGB332；双缓冲后4倍放大到640×480。8位预览有颜色量化和像素感，不是高清画质。
- HDMI时序仍为25MHz、800×525总周期，约59.52Hz。传感器有效帧率取决于曝光及配置；双缓冲拥塞时丢整帧，HDMI可重复上一完整帧，不保证逐一展示所有传感器帧。

顶部8像素状态条：黄=初始化中，红=配置/回读/视频看门狗异常，蓝=暂无完整新画面或超过约1秒未更新，绿=已有新鲜完整画面。无摄像头时也应有稳定HDMI底图，不能用底图证明摄像头工作。

底部8像素三组二进制计数，每组8格、低位在左：绿色为已显示帧（循环计数），红色为格式错误帧（饱和255），黄色为缓冲繁忙丢帧（饱和255）。有效丢帧允许，持续格式错误不正常。按S4可重新初始化。

## 可靠性和跨时钟

1. 先硬复位、等待启动，读取300A/B并核对5640；写252项寄存器，软件复位后等5ms，再回读输出宽高及RGB格式。任意NACK、超时、ID错误、回读错误均不置ready，等待后整套重试。
2. SCCB为开漏、100kHz，16位寄存器地址；读用重复START，最后一个字节由主机NACK。支持有界时钟拉伸；总线卡死不会阻塞音频。
3. PCLK直接采样DVP，完整检查每行640字节、240行及抽取像素数。拒绝奇数字节、短/长行、缺行/多行；同步后先丢弃4个连续正确帧，出错重新预热。
4. 两个独立双口RAM银行，发布完整帧后保持不动，HDMI只在垂直消隐时切银行并确认。确认前不写读银行；如果新帧第一个像素到来时没有空银行，整帧放弃。
5. 请求/确认采用双触发同步的单比特toggle。复位异步拉低、各域同步释放；PLL失锁会同时撤销配置和缓冲所有权。PCLK停止也能异步清除摄像头侧状态。
6. 约2秒收不到正确帧，配置控制器硬复位并重配；显示侧约1秒未更新会撤掉旧图，给出蓝色诊断底图。

`src/acg720_rgb_hdmi.sdc`约束PCLK最高50MHz（20ns），0x4740[5]=1在下降沿输出、上升沿采样，输入延迟预算0.5～5ns。独立PCLK与系统/RGB/HDMI域声明异步；同步器及持有的双口RAM数据实现真正的跨域传输，而不是仅靠时序例外掩盖直连。

## 源码、验证与发布

- 配置表来自本地小梅哥第59章RGB例程，保留厂商ISP、AWB、gamma与镜头校正值；修改为25MHz参考时钟对应的PLL倍频、4:3窗口及320×240尺寸。`tools/gen_ov5640_config.py`内含原表和源文件SHA256，可独立生成`src/generated/ov5640_qvga.mem`。
- 新RTL在`src/camera/`，均已列入GPRJ及两份CLI文件清单。CPU不处理图像，不增加菜单代码和软核RAM。
- `tb_ov5640_config`：引脚级ID/读写、252项配置、六项回读、主机NACK、重试、拉伸、错误ID/配置、缺设备、卡总线及停流重启。
- `tb_ov5640_capture`：字节顺序、抽取坐标、预热、失步、五种坏帧及半像素复位。
- `tb_camera_pipeline`：生产尺寸、异步快写慢读、逐像素比对、无撕裂、整帧丢弃、超时撤图和PLL恢复；PLL与ODDR仅为行为时钟模型，不代替电气实测。
- 原AI旋律的上次最差路径为variation→音程→轮廓→加法→限幅（19.9ns）。本次在音程与音高计算间加寄存级，增加20ns控制延迟；推理网络、权重和音乐规则不变，须通过旋律/音频回归。
