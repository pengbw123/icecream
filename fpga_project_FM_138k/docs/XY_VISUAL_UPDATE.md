# 延迟李萨如视觉更新

## 为什么选这个

本次按“FFT或者李萨如”的要求先实现后者。当前音源单声道复制左右，直接画L/R会退化为直线；采用X=s[n]、Y=s[n-delay]的延迟坐标，忠实反映PCM的相位轨迹，不伪造立体声，也不把轨迹叫作频谱。

显示完全由RTL完成，触摸软核只改VIEW和XY DELAY寄存器。没有改FM内核、音频更新率、16复音或听觉效果器；原先Dexed差分与PCM上传待办继续保留。

## 硬件流程

- 128深度的历史缓冲保留16bit PCM，延迟可调1～96样点；默认24样点=0.49152ms。
- 每次采集512个点，量化到256×128绘图区；用加减比较连接相邻点，每条线最多约256拍，低于1024拍音频间隔。
- 两个1bit位图银行共8KiB。清理空闲银行、画轨迹、发布请求；显示只在VBlank换银行，写端等确认后才改写旧银行。
- 视频侧同步读图，放大为512×256显示；原波形缓存和菜单/琴键/峰值/EG继续保留。
- 轨迹不做声音自动增益或音频滤波，静音中心点、低音量小轨迹是正常的。
- 该图展示约10.49ms声音片段的轨迹，不是长时间余辉示波器，不是FFT。多音时不会像单一正弦一样总形成简单椭圆。

## 稳定性修复

检查发现原波形握手只重置显示侧时，若视频PLL异常失锁，显示银行会回到1而写侧可能还在写1。现在视频失锁同时复位采集状态；音频时钟域的复位释放经过两拍同步，重新从安全银行开始。音源计算本身不随视频失锁复位。
菜单状态发布同时把负八度限制为4bit，避免符号扩展覆盖新增的VIEW/DELAY字段。

## 测试

- tb_audio_xy_scope：正弦波、24样点精确延迟、圆形轨迹四象限覆盖、银行清零及互斥检查。
- tb_rgb_visualizer：800×480有效像素、无未知RGB、缓存互斥，并注入PLL失锁/恢复；输出tmp/rgb_preview.ppm供查看，不是设计软件绘制的UI示意图。
- tb_touch_ui：真实RV32I固件，新增VIEW切换、延迟加1、长按不连发、切到负八度后视觉参数不被破坏的回归。
- 原串口、WS2812回归保持。

未上板验证面板、电源、Flash烧写和USB实际连接；仿真通过不能等价为这些操作已完成。

## 新布局结果

Logic17469（13%）、CLS13798（20%）、BSRAM56/340（17%）、DSP23.5/298（8%）。相较上一修复版新增4块BSRAM，DSP未增加。保持16复音和原FM内核。
50MHz域Fmax51.436MHz、33.333MHz像素域Fmax40.111MHz，setup/hold TNS均0。50MHz最差setup约0.558ns，时序并不宽裕，后续应优先分拍优化音源Note On初始化路径，而不是凭资源占用20%就直接扩复音。
