## 可以利用剩余资源做什么

1. **寄存器切断控制路径**：MIDI 入口用两项寄存器 FIFO，让输入 ready 只看寄存后的占用数。
   USB 移植已采用这一结构；约几十个数据 FF，无 BSRAM。全满同时出队时允许一个空拍。
   它隔离上游背压，但并不意味着所有 ARP→监测→SEQ 组合路径都已消失，最终仍检查 STA。
2. **给事件观察支路加流水寄存器**：接收握手后的 data/valid 成对寄存，再送练习、LED、SEQ 录音；
   可以缩短 ARP ready 到 SEQ 写口的路径，代价是几个时钟的明确延迟。此项为后续候选，尚未实施。
3. **分级算术与 DSP**：长乘法链拆级、音高/包络计算分摊，或增加独立运算通道，
   可以把 FF/DSP 换成时序余量/吞吐量。要同步相位、槽号、valid，不能只给数据加寄存器。
4. **小型 ROM/缓冲移到 LUT/FF**：适合浅小表和几项 FIFO；大音频延迟线改成 FF 会消耗大量逻辑和布线。
5. **算法图改为节点/连线实时绘制**：有机会释放 32KiB 图形 RAM，并减少软核中的同尺寸图形副本。
   这是减少 BSRAM、增加适量 LUT 运算的候选；当前未修改图形实现。
6. **缩减软核数据 RAM需先改布局**：当前 ELF 的 .text+.data 为 60,604B，.bss 为 36,420B，
   静态末端为 0x10017b00（约94.75KiB），另需栈。不能直接把128KiB改为64KiB。
   先减少图形暂存/重复常量，或重新组织只读/可写映射，再决定 RAM 容量。
7. **DDR 承担长延迟/大缓存**：可释放较多 BSRAM，但要增加控制器、预取 FIFO 和确定性调度。
   不应为了资源占用率随意压缩音频位宽或改变延迟参数。

USB 移植只落实了小型寄存器事件缓冲，不宣称以上候选优化已经全部完成。
