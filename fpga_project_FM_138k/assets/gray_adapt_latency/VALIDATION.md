# 灰度光照自适应与 USB MIDI 数字延迟验证

构建源码快照 `10261d8`。最终时序、资源、位流校验值及回退文件以 `docs/releases/2026-10-31_gray_adapt_latency.json` 为准。发布前核对工作源码、快照及固件镜像，所有约束时钟 setup/hold 必须通过；未自动烧录或推送。

| 验证 | 结果 |
|---|---|
| 光照补偿 RTL/Python 对齐 | 552 帧、565248 像素逐项一致，包含四角估计、黑端、增益下限、截断及重放顺序 |
| 灰度前端 | 全65536颜色转换、9216采样、异步时钟、坏帧/缺像素/忙帧丢弃、复位及PCLK停止 |
| 灰度 CNN | 552图片、2208分类分数与整数参考完全一致；固定18909时钟；忙时写入忽略及中途复位 |
| 生产控制器 | 26次真实RGB565→跨时钟→自适应→CNN→门限/投票/状态/动作回放，通过 |
| 拒识 | 106组有符号分数极值、同分、门限边界及OTHER；256种平灰度归一到白底并判OTHER |
| HDMI | 灰度预览、跨帧稳定、ROI边框、RAW赢家文字、原因文字和识别关闭恢复，通过 |
| 真实USB到音频 | 解码、去传输头、三路仲裁、FIFO、生产FM32、I2S；16个MIDI通道/cable及触屏，共17次成功测量 |
| 同引脚脉冲 | 每次高电平宽度逐时钟等于延迟计数；测试音色136469拍=2729.38us；不是板上模拟实测 |
| 测量异常 | 真实I2S最后一位终点、背压去重、非静音跳过、超时、重叠取消、清零及快照 |
| 真实RV32I菜单 | 统计值、清零、退出、键盘、力度、音量5、耳机选择及AI旋律预览，通过 |
| 蓝牙曲谱 | 8192容量、CRC、实际Android字节、实际UART时序、模式互斥、STOP背压及声部分离回归，通过 |

光照变换测试记录在 `adapt_stress.json`：新方案原始手势分类312/372，正确且过门限304/372；旧方案分别330/372与300/372。新方案半曝光正确接受304（旧277）、低对比302（旧214）、不均匀光照297（旧289）。这是同一公开测试集的人工变换，没有据此重选模型或门限；不能视作真实相机准确率。合成负样本误接受有增加，公开原图原始分类也下降，需实机权衡。

新训练由NumPy在本机CPU完成160轮，按留出验证集选择第114轮，未按测试集挑权重。训练及导出记录、随机种子、数据ZIP SHA256在 `src/generated/gesture_gray/training_report.json`。模型输入必须先经 `tools/gesture/gray_adapt.py` 或对应RTL，不能混用旧原始灰度模型流程。

光照补偿假设亮背景、暗手，不能恢复过曝信息，也不提供自动手部检测或任意杂乱背景适应。HDMI小窗仍显示原始传感器灰度，最终CNN输入在其后做补偿。

测量脉冲起点为已解码的板级事件接受时，不包括键盘扫描、USB轮询/CH376解包前段。终点为I2S数字起音，不含DAC/模拟滤波。模拟端到端5ms指标仍需示波器另一路测模拟输出。波形测量限单音、静音后触发；250ms超时和取消脉冲不能当成正常延迟。

本次未证明旧版USB不能触发的唯一实机根因；通过起点前移、统一数据格式、全通道回归和就绪诊断增强处理，仍需用户实板确认。未宣称实机手势UNKNOWN已经全部解决。黑白回退路径保留，默认未切换。
